# Требования к интеграции с платформой "Умный дом"

Этот документ описывает требования к интеграции между системой PropDevelopment и внешней партнерской платформой "Умный дом" для реализации функций интеллектуального домофона и шлагбаума.

## 1. Требования к безопасности

1.  **Шифрование канала связи**: Всё взаимодействие между `tenant-core-app` (сервис PropDevelopment) и API платформы "Умный дом" должно осуществляться исключительно по протоколу HTTPS с использованием TLS версии не ниже 1.2.
2.  **Изоляция данных (Multi-tenancy)**: API партнера должно гарантировать строгую изоляцию данных между различными жилищными комплексами и пользователями. Запросы от PropDevelopment, относящиеся к одному ЖК, не должны иметь никакой возможности получить или изменить данные другого ЖК.
3.  **Защита персональных данных**:
    *   Биометрические данные (фотографии лиц) и номера автомобилей являются чувствительными персональными данными. Их хранение и обработка на стороне партнера должны соответствовать законодательству РФ (152-ФЗ "О персональных данных").
    *   Данные должны храниться в зашифрованном виде (encryption-at-rest).
    *   Передача этих данных для регистрации в системе партнера должна происходить по защищенному каналу после явного согласия пользователя, полученного в мобильном приложении PropDevelopment.
4.  **Аудит и логирование**: Все операции, связанные с управлением доступом (открытие дверей/шлагбаумов) и изменением данных доступа (добавление/удаление лиц, номеров авто), должны логироваться на стороне партнера. У PropDevelopment должен быть доступ к этим логам через API для проведения аудита безопасности и разбора инцидентов.
5.  **Минимизация данных**: API партнера не должно возвращать избыточную информацию. Например, при запросе истории доступа должны возвращаться только необходимые поля (время, статус, идентификатор пользователя), но не полные профили пользователей.

## 2. Протоколы аутентификации и авторизации

1.  **Межсервисная аутентификация (System-to-System)**:
    *   Для взаимодействия между `tenant-core-app` и API "Умного дома" должен использоваться протокол **OAuth 2.0** в режиме **Client Credentials Flow**.
    *   PropDevelopment (в лице `tenant-core-app`) выступает в роли клиента. Ему выдается уникальный `Client ID` и `Client Secret` для получения токена доступа (Access Token) к API партнера.
    *   Токен должен иметь ограниченный срок жизни (например, 1 час) и запрашиваться заново по истечении срока.

2.  **Авторизация на стороне партнера**:
    *   API партнера должно выполнять авторизацию каждого запроса.
    *   `tenant-core-app` после аутентификации собственного пользователя (собственника) определяет его права и при запросе к API партнера передает идентификатор пользователя и/или устройства, с которым производится действие.
    *   Партнерская система на своей стороне должна проверить, имеет ли данный пользователь право на выполнение запрошенной операции (например, может ли собственник X открыть шлагбаум Y).

## 3. Организация взаимодействия

1.  **Архитектура взаимодействия**:
    *   Мобильное приложение собственника ("Витрина сервисов для собственников") взаимодействует только со своим бэкендом — `tenant-core-app`. Прямые вызовы от мобильного приложения к API партнера запрещены.
    *   `tenant-core-app` выступает в роли Backend-for-Frontend (BFF), проксируя и обогащая запросы к партнерской системе.
2.  **Протокол взаимодействия**: Взаимодействие осуществляется по протоколу **REST/JSON** поверх HTTPS.
3.  **Основные сценарии и API-методы**:
    *   **Открытие двери/шлагбаума**:
        *   `POST /devices/{deviceId}/open` - отправка команды на открытие. `deviceId` - уникальный идентификатор домофона или шлагбаума.
    *   **Просмотр истории доступа**:
        *   `GET /devices/{deviceId}/history?user={userId}` - получение истории событий для конкретного устройства или пользователя.
    *   **Управление данными для распознавания**:
        *   `POST /users/{userId}/biometrics` - добавление фото лица для распознавания.
        *   `POST /users/{userId}/vehicles` - добавление номера автомобиля.
        *   `DELETE /users/{userId}/biometrics/{bioId}` - удаление биометрических данных.
    *   **Обратные вызовы (Webhooks)**: Для асинхронных событий, таких как попытка доступа незарегистрированного пользователя, платформа "Умный дом" может использовать веб-хуки для уведомления системы PropDevelopment.
        *   `POST /prop-dev-webhook/access-denied` - уведомление о попытке несанкционированного доступа.
